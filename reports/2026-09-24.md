## Trending Papers

**Disaggregated Quantization: Specializing LLM Prefill and Decode** — https://arxiv.org/abs/2609.26333
Panferov et al. (IST-DASLab, Sept 22): shows that prefill and decode reward fundamentally different quantization strategies and proposes applying them independently — low-precision arithmetic for prefill, compact weight storage for decode — with an NVFP4 prefiller for Qwen3.8-27B that improves 1-bit decode accuracy by 32.5 points on MMLU-Pro.
*Why it matters for practitioners:* If you are already running prefill-decode disaggregated serving (or planning to), this paper gives you a concrete recipe to recover significant accuracy at 2–3-bit decode without any change to your decode checkpoint.

**Agent-Editing World Model: Rethinking World Modeling for LLM Agents** — https://arxiv.org/abs/2609.28416
Proposes AEWM, which models how reasoning and actions shape future task progress — rather than predicting tool responses — and uses an "Action Judge + State Revision" loop to eliminate task-state contamination (outdated plans persisting in agent history); achieves 70.5% macro-F1 on its benchmark and 3.2–6.7 pt improvement across six benchmarks and three agent backbones.
*Why it matters for practitioners:* Addresses one of the most practically painful failure modes in long-horizon agents — stale assumptions accumulating in context and derailing later steps — and provides a reproducible fine-tuning recipe (AEWM-RFT via rejection sampling).

**Crossflow: Prefill–Decode Elasticity for Agentic LLM Serving** — https://arxiv.org/abs/2609.27085
From Meta; quantifies that real agentic workloads exhibit up to 4.7x peak-to-mean ratio in uncached input/output tokens at minute timescales and 24.5x intra-day variation, showing that static P/D pool sizing leaves 17% of cluster capacity idle or creates queueing; proposes elastic cross-assignment.
*Why it matters for practitioners:* Static prefill-decode disaggregation — the current default for high-throughput serving — is tuned for batch inference, not agent traffic; this paper gives the empirical case and a practical solution for teams running agentic workloads at scale.

**BenchMIRT: What are LLM Benchmarks Actually Measuring?** — https://huggingface.co/blog/allenai/benchmirt
AllenAI (September 1): introduces a method for auditing LLM benchmarks at the level of individual prompts, identifying which questions are ambiguous, contaminated, or measuring something other than the intended capability.
*Why it matters for practitioners:* Benchmark-driven model selection is the default practice — understanding that individual benchmark items can be systematically misleading (and having a tool to flag which ones) changes how teams should interpret eval results and build internal evals.

**CompKV: Compensation-Aware KV Selection for Long-Context LLM Inference** — https://arxiv.org/pdf/2609.28416
Proposes selecting KV cache entries to retain during long-context inference by estimating the error that eviction would introduce and compensating for it, rather than using attention-score heuristics alone.
*Why it matters for practitioners:* As context windows and agentic episode lengths grow, KV cache management becomes a first-order cost and latency problem; compensation-aware selection is a principled improvement over evict-the-lowest-attention-score baselines in production systems.
