# Daily AI Update — 2026-07-26

## Trending GitHub Repositories

**karpathy/autoresearch** — <https://github.com/karpathy/autoresearch>
An AI agent that runs autonomous overnight experiments on the nanochat single-GPU LLM training setup, iterating on code changes, measuring validation loss, and keeping only improvements — it discovered ~20 additive improvements in a 2-day run, cutting "time to GPT-2" from 2.02 h to 1.80 h.
*Why it matters for practitioners:* This is on-policy self-improvement applied to training itself — a concrete existence proof that an agent loop can drive ML research, shifting the mental model of who (or what) runs the ablation cycle.

**microsoft/SkillOpt** — <https://github.com/microsoft/SkillOpt>
A text-space optimizer that trains reusable natural-language skills for frozen LLM agents: a frontier model converts agent trajectories into bounded add/delete/replace edits, a held-out validation gate accepts only edits that improve performance, and the result is exported as a portable `best_skill.md` artifact — now integrated into VSCode Copilot.
*Why it matters for practitioners:* Skills become trainable external agent state with zero inference overhead, giving teams a path to improve agent behavior on custom tasks without touching model weights or prompt templates.

**JustVugg/colibri** — <https://github.com/JustVugg/colibri>
A ~2,400-line pure-C inference engine (no BLAS, no CUDA, no Docker) that runs GLM-5.2 (744B MoE) on a consumer machine with 25 GB of RAM by streaming experts from an NVMe SSD on demand, treating disk + RAM + VRAM as a unified memory hierarchy.
*Why it matters for practitioners:* It breaks the assumption that frontier-scale MoE models require server-grade hardware — local inference of a 744B model on a laptop-class RAM budget is now a single `gcc` compile away.

**diegosouzapw/OmniRoute** — <https://github.com/diegosouzapw/OmniRoute>
A free MIT-licensed AI gateway exposing one OpenAI-compatible endpoint across 290+ providers (90+ free), with 18 routing strategies, 4-tier automatic fallback, and RTK+Caveman stacked compression claiming 15–95% token reduction on tool-heavy sessions.
*Why it matters for practitioners:* Single-endpoint routing with quota-aware fallback removes vendor lock-in risk from agent pipelines; the aggressive token compression needs careful evaluation for nuanced tasks but is significant for boilerplate-heavy tool calls.

**karpathy/nanochat** — <https://github.com/karpathy/nanochat>
The minimal end-to-end LLM training harness — tokenization, pretraining, SFT, RL, KV-cache inference, and a ChatGPT-like UI in ~630 lines — with a single `--depth` dial that auto-configures all other hyperparameters for compute-optimal training; reproduces GPT-2-class capability for ~$48.
*Why it matters for practitioners:* The new canonical "learn-from-scratch" baseline for anyone who wants to understand or benchmark LLM training end-to-end without wading through a production codebase.

## Trending Papers

**SkillOpt-Lite: Better and Faster Agent** — <https://arxiv.org/abs/2607.03451>
Accelerates the SkillOpt agent-skill optimizer by grounding it in zeroth-order optimization theory (mapping trust-region and central-difference analogues to skill edits), achieving +8.8 pts on GPT-5.5 and +25.4 pts on GPT-5.4-nano on LiveMath — enough for nano to surpass standard GPT-5.4 tuned with full SkillOpt.
*Why it matters for practitioners:* The Lite variant makes skill optimization practical at the nano model tier, meaning teams can run the loop on cheap inference while still getting frontier-level task performance on their custom workflows.

**Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions** — <https://arxiv.org/abs/2507.05257>
Introduces MemoryAgentBench, a benchmark that tests four distinct memory competencies — accurate retrieval, test-time learning, long-range understanding, and conflict resolution — through incrementally-accumulated multi-turn interactions designed to expose failure modes that static book-QA benchmarks miss; accepted at ICLR 2026.
*Why it matters for practitioners:* Most existing evaluations lump "memory" together; this paper shows the four competencies pull apart cleanly — a system that aces retrieval can still fail conflict resolution — which directly informs how to select or architect memory modules for production agents.

**SLAI T-Rex: Full-Parameter Post-training of the DeepSeek-V4 Family on Ascend SuperPOD** — <https://arxiv.org/abs/2607.20145>
End-to-end training optimization for trillion-parameter MoE post-training on Ascend NPUs: a hierarchical framework spanning model parallelism, computation-communication overlap, and kernel-level tuning, achieving 34.22% MFU — a 2.93× improvement over the open-source baseline — while maintaining training stability; trending #1 on HuggingFace papers.
*Why it matters for practitioners:* A detailed map of where MFU is lost at trillion-parameter scale (communication non-overlap, memory pressure, kernel inefficiency) that applies beyond Ascend — the optimization hierarchy is directly transferable to any large-scale distributed MoE setup.

**On-Policy Distillation with Curriculum Turn-level Guidance for Multi-turn Agents** — <https://arxiv.org/pdf/2606.15912>
A training method for multi-turn LLM agents that applies curriculum-aware turn-level supervision during on-policy distillation, gradually introducing harder guidance signals as the student improves, outperforming standard on-policy and off-policy distillation baselines on agentic benchmarks.
*Why it matters for practitioners:* On-policy distillation is the dominant post-training approach for agents, and turn-level curriculum control is a concrete technique for avoiding the instability and reward hacking that often derails naive on-policy loops.

**A Formula-Driven Survey and Research Agenda for On-Policy Distillation** — <https://arxiv.org/pdf/2606.22793>
A unifying formal treatment of on-policy distillation methods for LLMs — MAD-OPD, SAGE-OPD, TCOD, Skill-SD, and others — expressed through a common mathematical framework, mapping classical counterparts (trust regions, central differences) to text-space analogs and identifying open research directions.
*Why it matters for practitioners:* Rather than treating each recent on-policy method as a separate framework, this survey gives a single vocabulary that lets teams compare approaches, diagnose failure modes, and reason about which variant fits their agent task.
