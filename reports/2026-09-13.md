## Trending Papers

**LLMZero: Discovering Adaptive Training Strategies for RL Post-Training via LLM Agents** — https://arxiv.org/abs/2606.18388
An agentic system that uses LLM agents and tree search to discover optimal RL post-training hyperparameter schedules by diagnosing training pathologies at each checkpoint.
*Why it matters for practitioners:* Improves over grid search by 6–15% relative on GRPO tasks and outperforms random search under matched compute—this is automated ML for the post-training loop, not just another hyperparameter tuner.

**Retrospective Progress-Aware Self-Refinement (RePro) for LLM Agent Training** — https://arxiv.org/abs/2606.14302
A training framework where agents generate their own step-wise progress signals retrospectively—after seeing the full trajectory outcome—rather than predicting progress online.
*Why it matters for practitioners:* The key empirical finding (online prompting hurts 8.6%, retrospective demonstrations help 7.9%) gives practitioners a concrete, actionable signal: inject progress reasoning at training time, not inference time.

**SIRI: Self-Internalizing Reinforcement Learning with Intrinsic Skills for LLM Agent Training** — https://arxiv.org/abs/2606.02355
A three-phase RL framework that has agents mine reusable skills from their own successful trajectories and distill them directly into weights—eliminating the need for an external skill bank at inference.
*Why it matters for practitioners:* Removing a persistent skill retrieval system from the agent loop cuts context length, latency, and deployment complexity, making skill-augmented agents practical to ship.

**MemGraphRAG: Memory-based Multi-Agent System for Graph Retrieval-Augmented Generation** — https://arxiv.org/abs/2606.00610
A multi-agent RAG system (presented at KDD 2026) where agents share a unified memory context during graph construction, allowing them to resolve logical conflicts and maintain structural consistency across a corpus.
*Why it matters for practitioners:* The shared-memory design addresses the quality problem that plagues naive graph RAG—individual agents working in isolation produce inconsistent graphs; giving them shared state fixes the root cause.

**Neglected Free Lunch from Post-training: Progress Advantage for LLM Agents** — https://arxiv.org/abs/2606.26080
Demonstrates that progress-awareness signals already implicit in post-training trajectories are routinely discarded, and shows how surfacing them yields consistent performance gains without additional data.
*Why it matters for practitioners:* If the improvement is genuinely "free"—available from existing trajectories with a cheap re-labeling step—this becomes a near-zero-cost upgrade for any team already doing RL post-training on agents.
