## Trending Papers

**BATON: Dual-Axis Policy Optimization for LLM Agents** — https://arxiv.org/abs/2609.19830
Identifies two independent optimization axes in RL-based LLM agent training — intra-trajectory feedback attribution (Bayesian Attribution) and inter-trajectory objective aggregation (Trajectory Mass Normalization) — each yielding independent gains over GRPO and GiGPO baselines on ALFWorld, WebShop, and SearchQA.
*Why it matters for practitioners:* If you're training RL-based agents, BATON's decomposition shows that how you credit rewards across steps and how you weight trajectories across batches are separable levers — fixing either alone gives gains, and combining them consistently outperforms existing methods at all model scales.

**Does Your Agent's Memory Survive a Model Upgrade? A Controlled Study of Memory Portability** — https://arxiv.org/abs/2609.05339
Finds that fixed-schema memory structures transfer reliably across model upgrades, but compressed note-based representations are highly model-coupled — and the performance impact is asymmetric: A→B and B→A swaps produce different degradation.
*Why it matters for practitioners:* Any team using agent memory in production needs to know this before upgrading their underlying model — your memory store's format choice determines whether you can swap models without re-building or re-testing the memory pipeline.

**Retrieval-Driven Memory Reconsolidation for Long-Term LLM Agents** — https://arxiv.org/abs/2609.16053
Proposes triggering memory reorganization at retrieval time — progressively restructuring related memory units into coherent local structures — rather than treating memory as a passive read operation that only changes when new information arrives.
*Why it matters for practitioners:* This reframes agent memory architecture: retrieval isn't just a read, it's also a write opportunity — and using retrieval as a driver of memory evolution consistently improves performance on long-horizon tasks without changing the retrieval interface.

**Mixture-of-Experts Language Models Can Be Strong and Efficient Retrievers** — https://arxiv.org/abs/2609.13486
Finds MoE retrievers outperform dense retrievers with comparable active parameter counts by up to 3.0 nDCG@10 on BEIR, with experts for query encoding prunable without retraining or re-indexing while retaining >99% retrieval effectiveness.
*Why it matters for practitioners:* If you're building RAG systems and already using MoE models, using the same model as the retriever — rather than a separate embedding model — may outperform the dense alternative with fewer active parameters and lower query latency.

**Data-Efficient Training by Evolved Sampling** — https://arxiv.org/abs/2509.23461
Dynamic batch-level data selection framework that selects informative samples during training based on loss dynamics and augmented loss differences, requiring no expensive pre-computation; achieves up to ~45% wall-clock savings across pre-training and post-training tasks.
*Why it matters for practitioners:* A 45% training time reduction with no architecture change and minimal implementation overhead is the kind of result that changes the economics of fine-tuning and continued pre-training — particularly relevant for teams doing on-policy or iterative training runs.
