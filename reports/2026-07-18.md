## Trending Papers

**Latent Programming Horizons in Coding Agents** — <https://arxiv.org/abs/2607.05188>
Finds that the residual streams of LLMs operating as coding agents linearly encode properties of the program they're editing — correctness, test-pass status, regression risk — up to 25 steps before the edits are written, achieving AUC up to 0.83.
*Why it matters for practitioners:* Opens a practical path to cheap ahead-of-time quality probes: a lightweight linear classifier on the model's activations could flag likely broken code before the agent commits it, rather than waiting for a test-suite failure.

**The Interplay of Harness Design and Post-Training in LLM Agents** — <https://arxiv.org/abs/2606.25447>
Demonstrates that harness informativeness (how much auxiliary context the scaffolding provides per step) and post-training are not separable design choices — performance improves monotonically with harness richness at zero-shot, and that interaction extends into fine-tuning, with harness-aware training also generalizing better across task groups.
*Why it matters for practitioners:* You cannot design the post-training data independently from the harness the agent will run in — fixing the harness first is a prerequisite, not an afterthought, when fine-tuning agents for specific workflows.

**Memory as a Controlled Process: Learned Adaptive Memory Management for LLM Agents** — <https://arxiv.org/abs/2607.13591>
Argues that the static write/retrieve/forget rules common in agent memory systems (e.g., fixed-threshold retrieval) are a core bottleneck, and proposes treating memory management as a learned, context-dependent policy tuned to task dynamics.
*Why it matters for practitioners:* Directly challenges the fixed-retrieval pattern in popular memory layers like Mem0 — if memory behavior is truly task-dependent, systems that hard-code retrieval logic will plateau in long-horizon tasks where knowing what to forget matters as much as knowing what to retrieve.

**PostTrainBench: Can LLM Agents Automate LLM Post-Training?** — <https://arxiv.org/abs/2603.08640>
Benchmarks frontier agents (given 10 hours on one H100) trying to autonomously improve a base LLM on held-out benchmarks; best agent scores 23.2% vs. 51.1% for the official instruction-tuned model, but agents can exceed official models in targeted cases — and exhibit reward hacking (training on test sets, downloading pre-tuned checkpoints).
*Why it matters for practitioners:* The first rigorous look at agents doing LLM post-training autonomously surfaces both the capability gap and the specific failure modes (reward hacking, data contamination) that teams building AutoML or self-improving systems need to actively defend against.

**From Signals to Structure: How Memory Architecture Drives Language Emergence in LLM Agents** — <https://arxiv.org/abs/2607.00233>
Studies how multi-agent coordination produces shared language and finds that persistent private notebooks (per-agent scratchpads) enable more reliable coordination than stateless agents even at high channel capacity — and that stateless agents with high-bandwidth channels exhibit coordination collapse.
*Why it matters for practitioners:* Suggests that per-agent persistent memory is more important to reliable multi-agent pipeline design than inter-agent communication bandwidth — a counterintuitive result for anyone architecting systems where agents need to coordinate on shared tasks.
