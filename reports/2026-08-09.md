## Trending Papers

**DreamGuard: Efficient Runtime Guardrail for LLM Agents via Risk-Aware World Model** — https://arxiv.org/abs/2608.05695
A proactive safety layer for LLM agents that maintains a compact recurrent world model over the agent's trajectory, predicts future risk states, and intervenes before hazardous actions execute — achieving 25ms per-call latency.
*Why it matters for practitioners:* Most existing guardrails are reactive (check the current action in isolation), which is blind to long-horizon drift where individually-benign actions accumulate into dangerous states; DreamGuard's recurrent latent world model is the first lightweight architecture to address this gap, making runtime safety tractable for deployed agents.

**Osprey: Production-Ready Agentic AI for Safety-Critical Control Systems** — https://arxiv.org/abs/2508.15066
A framework for deploying agentic AI at Lawrence Berkeley National Lab for large-scale facility control: plan-first orchestrator for human review before hardware is touched, dynamic tool selection, and data-type-consistent coordination between subsystems.
*Why it matters for practitioners:* One of the first honest engineering write-ups of agentic AI in a real high-stakes production environment — the tradeoffs (plan-first vs. reactive, compactness vs. capability) are described with enough specificity to inform your own production agent design.

**When Does Multi-Agent RL Improve LLM Workflows?** — https://arxiv.org/abs/2605.24202
Systematically examines when jointly training specialized agent roles with RL improves end-task accuracy vs. when it introduces instability that is worse than the un-trained baseline.
*Why it matters for practitioners:* The paper gives concrete conditions under which multi-agent RL helps — if you are building a multi-agent system and considering joint RL fine-tuning, this is required reading before committing to that path.

**Unifying Data, Memory, and Compute Efficiency in LLM Training: A Survey** — https://arxiv.org/abs/2606.10706
Organizes the 2025-2026 literature around three coupled training bottlenecks — data efficiency (selection and pruning), memory efficiency (fitting training into hardware), and compute budget awareness — with practical guidance on which methods compose well.
*Why it matters for practitioners:* If you are planning or running an LLM training run, this is the map of available tools across all three dimensions; the coupling analysis tells you which choices propagate into downstream constraints.

**AgentAtlas: Beyond Outcome Leaderboards for LLM Agents** — https://arxiv.org/abs/2605.20530
Proposes process-level evaluation metrics that track how an agent reasons and recovers across a trajectory, rather than only scoring the binary final outcome.
*Why it matters for practitioners:* Outcome-only benchmarks are easily gamed and don't differentiate between an agent that barely scraped a correct answer from one with robust reasoning; process-level metrics give you actionable signal for debugging and improving agent behavior.
