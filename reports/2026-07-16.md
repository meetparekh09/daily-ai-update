## Trending GitHub Repositories

**karpathy/autoresearch** — <https://github.com/karpathy/autoresearch>
An autonomous agent loop that proposes code changes to a nanochat training setup, runs a 5-minute training job, measures whether loss improved, commits or rolls back, and repeats—running 700 experiments in 2 days and discovering 20 training optimizations with no human in the loop.
*Why it matters for practitioners:* This is a concrete, runnable proof that on-policy self-improvement for LLM training is tractable today on a single GPU; if you're doing model training research, you can point this at your own training code tonight.

**xai-org/grok-build** — <https://github.com/xai-org/grok-build>
xAI open-sourced Grok Build (844k lines of Rust) on July 15 after a security incident showed the CLI was silently uploading entire git repos—including SSH keys and secret files—to xAI's cloud regardless of the user-facing "opt-out" toggle.
*Why it matters for practitioners:* The code shows how a production coding agent handles data at scale, and the incident is a direct lesson on the gap between what AI tools claim to do with user data and what they actually do at the network level.

**Giskard-AI/giskard-oss** — <https://github.com/Giskard-AI/giskard-oss>
Open-source Python library for evaluation and red-teaming of LLM agents—auto-generates adversarial test suites from a plain-language agent description and scans for prompt injection, harmful content, and misinformation vulnerabilities.
*Why it matters for practitioners:* Traditional unit tests don't work for non-deterministic agents; this gives you a structured way to define, run, and track evals against your agent before and after changes.

**karpathy/nanochat** — <https://github.com/karpathy/nanochat>
A minimal, single-file, full-stack LLM training and inference pipeline covering tokenization, pretraining, supervised fine-tuning, evaluation, and CLI inference—designed to train a capable chat model for under $100 on a single GPU node.
*Why it matters for practitioners:* If you want to understand (or modify) every step of the modern LLM training stack without a research team or six-figure cloud budget, this is the reference codebase—it's what autoresearch uses as its substrate.

**asgeirtj/system_prompts_leaks** — <https://github.com/asgeirtj/system_prompts_leaks>
A CC0 public archive of extracted system prompts from 45+ major AI products across Anthropic, OpenAI, Google, xAI, Microsoft, Cursor, and Perplexity—with structured vendor folders updated as new model versions ship.
*Why it matters for practitioners:* Reading how frontier labs actually prompt their production systems (not just how they say they do) reveals patterns and constraints that are useful when designing your own agent system prompts.

## Trending Papers

**Safety Testing LLM Agents at Scale: From Risk Discovery to Evidence-Grounded Verification** — <https://arxiv.org/abs/2607.01793>
Presents Vera, an automated three-stage pipeline that discovers risks, generates executable safety test cases, and provides evidence-grounded verification—evaluated on four production agent frameworks (OpenClaw, Hermes, Codex, Claude Code), yielding 1,600 test cases across 124 risk categories.
*Why it matters for practitioners:* The finding that multi-channel attacks achieve 93.9% average success rates across production agent frameworks is a wake-up call; Vera-Bench gives you a concrete benchmark to test your own agent before shipping it.

**Measuring Harness-Induced Belief Divergence in Multi-Step LLM Agents** — <https://arxiv.org/abs/2607.04528>
Empirically demonstrates that the scaffolding layer around an LLM agent—tool call formatting, message history truncation, system prompt injection—systematically shifts the model's belief distribution across steps in ways that compound and are not visible from single-step evals.
*Why it matters for practitioners:* If you're seeing unexpected behavior in multi-step agents but your single-call evals look fine, this paper names the mechanism; it argues that harness design is a first-class variable, not a neutral wrapper.

**Qwen-AgentWorld: Language World Models for General Agents** — <https://arxiv.org/abs/2606.24597>
Proposes training language world models (LWMs) that can simulate environment dynamics in language space, enabling agents to plan and self-improve via imagined rollouts rather than costly real-environment interaction.
*Why it matters for practitioners:* Using a world model as a cheap simulation environment for agent training is a scalable alternative to real-environment data collection; this is an architecture that could significantly reduce the data cost of training capable agents.

**Benchmarks are Not Enough: RAMP for Runtime Assessing of Agentic Models in Production Systems** — <https://arxiv.org/abs/2605.27492>
Argues that static offline benchmarks systematically underestimate production agent failure rates and proposes RAMP, a framework built on the OpenHands SDK that runs agents against continuously refreshed, runtime-observable tasks drawn from real production workflows.
*Why it matters for practitioners:* If you're using benchmark scores to make deployment decisions about your agent, this paper shows why those scores are optimistic—and gives you a tool for grounding evaluation in what actually happens in production.

**On-Device Deep Research at 4B** — <https://arxiv.org/list/cs.AI/current>
Demonstrates a deep research agent—capable of multi-hop retrieval, synthesis, and citation—running within a 4-billion-parameter model entirely on-device, quantifying tradeoffs between retrieval exposure, faithfulness, and coverage at this scale.
*Why it matters for practitioners:* This collapses the assumption that deep research agents require frontier-scale models; it opens a path to private, low-latency research agents deployable on edge hardware.
