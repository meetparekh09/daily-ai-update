## Trending Papers

**Molt: A Scalable PyTorch-Native Training Framework for Agentic Reinforcement Learning** — https://arxiv.org/abs/2607.21653
NVIDIA NeMo's technical report for Molt, a from-scratch agentic RL training stack built around three components — Ray for async scheduling, vLLM for rollout, FSDP2 for training — that fits in ~8,600 lines and matches Megatron performance at trillion-parameter MoE scale.
*Why it matters for practitioners:* The paper establishes that you don't need 60,000-line frameworks to run frontier-scale agentic RL; the "trainer never sees a token it didn't generate" invariant is a principled design choice that fixes a class of silent distribution shift bugs most teams encounter without realizing it.

**Skill Self-Play: Pushing the Frontier of LLM Capability with Co-Evolving Skills** — https://arxiv.org/abs/2607.22529
A Qwen team paper (July 24) introducing Skill-SP, a co-evolutionary RL loop with a proposer, solver, and dynamic skill controller that pushes LLM capability without human-labeled data by treating skills as verifiable mid-level task abstractions.
*Why it matters for practitioners:* This is the clearest recent evidence that the "environment-bound methods get precise rewards but stay narrow / open-ended methods generalize but have unreliable rewards" dilemma has a principled escape route — skill decomposition — which has direct implications for designing self-improvement loops in production agents.

**Self-Evolving World Models for LLM Agent Planning** — https://arxiv.org/abs/2606.30639
Introduces WorldEvolver, a framework that adapts a world model at deployment time via episodic memory (retrieval-based simulation), semantic memory (persistent rules extracted from prediction mismatches), and selective foresight (filtering low-confidence predictions before they enter agent context) — evaluated on ALFWorld and ScienceWorld.
*Why it matters for practitioners:* Unlike prior work that requires retraining the world model, WorldEvolver freezes both the agent and world model parameters and improves through context; this pattern — adapt the context window, not the weights — is increasingly the practical path for deploying long-horizon agents in dynamic environments.

**DataPrep-Bench: Benchmarking LLMs as Training Data Preparators** — https://arxiv.org/abs/2607.20465
The first benchmark jointly evaluating LLMs on both data construction (transforming raw sources into supervised training data) and data quality evaluation (predicting training value before fine-tuning); introduces the Distributional Alignment Score (DAS) and a Data-Construction-Skill agent that lifts baseline quality by ~20 points absolute on Llama-3.1-8B Finance.
*Why it matters for practitioners:* Most teams treat data prep as a manual step; this benchmark reveals that LLM-driven data prep is already measurably better than standard baselines and provides a shared protocol for comparing approaches — the kind of result that should shift where engineering effort goes in training pipelines.

**Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions** — https://arxiv.org/abs/2507.05257
A benchmark (July 2026) that evaluates agent memory through incrementally complex multi-turn scenarios — testing how agents memorize, update, and retrieve long-term information across sessions — addressing the absence of standardized memory evaluation in existing agent benchmarks.
*Why it matters for practitioners:* Agent memory is the least-evaluated component of production agent systems; this paper provides the first principled protocol for measuring it, which matters immediately for anyone evaluating memory layers like Mem0 or custom retrieval stacks.
