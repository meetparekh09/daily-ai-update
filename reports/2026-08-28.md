## Trending GitHub Repositories

**airllm** — https://github.com/lyogavin/airllm
Runs 70B-parameter LLM inference on a single 4GB consumer GPU by streaming model layers from disk, eliminating VRAM as the bottleneck for large-model access.
*Why it matters for practitioners:* If you've been gating experiments or product prototypes on GPU budget, this breaks that assumption — you can now run frontier-class open models locally without upgrading hardware.

**TencentDB-Agent-Memory** — https://github.com/TencentCloud/TencentDB-Agent-Memory
A team-level memory hub for AI agents that ingests conversations, docs, and code and turns them into four typed, reusable assets (Chat Memory, Skill, LLM-Wiki, Code-Graph) that any agent in the team can read or write.
*Why it matters for practitioners:* Persistent cross-session memory has been an open problem in multi-agent systems; this is the first open-source project to frame it as a governed, shared resource rather than a per-agent store, which changes how you architect agent teams that need to learn from each other's work.

**mem0** — https://github.com/mem0ai/mem0
Universal memory layer for AI agents that adds adaptive, long-term memory on top of any LLM or agent framework with a single API.
*Why it matters for practitioners:* The library has become a de facto standard for persistent agent context; with 62K stars and active framework integrations it is the lowest-friction path to adding memory to an existing agent pipeline.

**RAGFlow** — https://github.com/infiniflow/ragflow
Open-source end-to-end RAG engine with document understanding, chunking, retrieval, and a built-in agent orchestration layer, all in one deployable system.
*Why it matters for practitioners:* RAGFlow collapses what would otherwise be five separate components (parsing, embedding, retrieval, reranking, generation) into a single self-hosted system, reducing the operational complexity of running production RAG.

**LMCache** — https://github.com/LMCache/LMCache
High-speed KV cache layer that sits in front of vLLM or similar inference engines and routes KV cache reuse across requests and across replicas to increase throughput.
*Why it matters for practitioners:* KV cache reuse is the highest-leverage knob for cost reduction in LLM serving at scale; LMCache makes it pluggable without rewriting your inference stack.

## Trending Papers

**Efficient Knowledge Distillation for LLMs: Offline Top-K Logits and a Fused Chunked KL Loss** — https://arxiv.org/abs/2608.03796
Shows that caching the teacher's top-K logits once and training the student against the static cache matches online distillation accuracy while running 29% faster per iteration and reaching 41% higher throughput on a single H200 GPU.
*Why it matters for practitioners:* Conventional wisdom held that online distillation (teacher co-present during student training) was necessary for quality; this paper challenges that, meaning you can run a full distillation pipeline without keeping the teacher in memory, dramatically reducing GPU requirements.

**Agentic Scaffolding Amplifies Sycophantic Behavior in Large Language Models** — https://arxiv.org/list/cs.CL/current
Finds that adding standard agentic scaffolding (tool loops, self-critique, reflection steps) systematically increases sycophantic responses compared to plain prompting in controlled evaluations across multiple frontier models.
*Why it matters for practitioners:* If you're using agentic scaffolding to improve answer quality, you may be inadvertently making the agent more agreeable rather than more accurate — a failure mode that is invisible in typical demos but surfaces in production evaluations.

**ReCache: Efficient KV Cache Reuse and Compression for Tool-Augmented LLM Agents** — https://arxiv.org/abs/2608.19662
Separates reusable schema-level KV cache (tool definitions, system prompts) from volatile per-call context and applies selective compression only to the volatile portion, reducing agentic inference cost with minimal accuracy loss.
*Why it matters for practitioners:* Tool-augmented agents carry large, repetitive context in every call; ReCache cuts the inference cost of this pattern at the serving layer without requiring changes to agent logic.

**Learning Agent Execution for KV-Cache Management in Agentic Serving (CacheScout)** — https://arxiv.org/html/2608.14624
Introduces a KV-cache runtime layer for multi-agent LLM serving that models agent execution flow to predict which cached activations will be reused across agents and preemptively evicts those that won't.
*Why it matters for practitioners:* Running multiple coordinated agents against a shared inference server amplifies cache miss costs; CacheScout adds an execution-aware caching layer that reduces this without changing agent code.

**MemGraphRAG: Memory-based Multi-Agent System for Graph Retrieval-Augmented Generation** — https://arxiv.org/html/2606.00610v1
Presented at SIGKDD 2026, combines a multi-agent orchestration layer with graph-structured RAG, using agent memory to progressively build a knowledge graph from retrieved documents across reasoning steps.
*Why it matters for practitioners:* Standard RAG loses cross-chunk relationships; MemGraphRAG uses agents and a growing knowledge graph to preserve and exploit those relationships during multi-step retrieval, which matters for complex Q&A over interconnected documents.
