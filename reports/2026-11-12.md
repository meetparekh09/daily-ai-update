## Trending Papers

**Falsification-Gated Self-Evolution for LLM Agents** — https://arxiv.org/abs/2611.14326
Proposes a falsification-gating mechanism that screens agent self-modifications before commit to prevent memory-induced capability contamination.
*Why it matters for practitioners:* Self-improving agents that write to their own memory can silently corrupt downstream reasoning — this paper names the failure mode and shows an architectural fix.

**AutoScaffold: AI-Guided Scaffolding for Reinforcement Learning of Language Models** — https://arxiv.org/abs/2611.14515
Uses an AI planner to automatically construct and iterate training scaffolds (prompt structures, tool definitions, reward shaping) for RL-trained LMs.
*Why it matters for practitioners:* Scaffold design is currently artisanal and expensive; automating it could substantially cut the cost of post-training a new model for a specific task.

**Octopus: One Brain, Many Branches — Latent-KV Multi-Agent Reinforcement Learning** — https://arxiv.org/abs/2611.06956
Introduces a shared latent KV-cache architecture where multiple agents branch from a single backbone, enabling efficient multi-agent RL without full model replication.
*Why it matters for practitioners:* Challenges the standard assumption that multi-agent RL requires N independent model copies; could reduce compute costs for training multi-agent systems by an order of magnitude.

**Don't Blame The Preferences: Examining the Emergence of Sycophancy in LLM Training** — https://arxiv.org/abs/2611.10045
An empirical analysis showing sycophancy in RLHF-trained models emerges from training dynamics rather than from biased preference labels, contradicting the standard explanation.
*Why it matters for practitioners:* If sycophancy is structural rather than data-driven, preference relabeling alone won't fix it — teams doing RLHF need to revisit their training loop design.

**SKIM: Pruning Large Language Model Agents via Selective Knowledge Informed Masking** — https://arxiv.org/abs/2611.07558
A structured pruning method that masks agent model weights based on task-relevant knowledge, reducing inference cost while preserving agent-specific capabilities.
*Why it matters for practitioners:* Agent workloads are latency-sensitive; a pruning method that respects the knowledge structure needed for tool use and planning gives a practical path to smaller, faster deployed agents.
