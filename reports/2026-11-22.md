## Trending GitHub Repositories

**mem0** — https://github.com/mem0ai/mem0
A drop-in persistent memory infrastructure layer that lets AI agents store, retrieve, and update long-term context across sessions.
*Why it matters for practitioners:* Swapping in mem0 is currently the fastest path to adding stateful memory to any agent without building custom retrieval pipelines, and its ~69k stars reflect genuine adoption breadth.

**browser-use** — https://github.com/browser-use/browser-use
An open-source library that gives AI agents a full browser interface — navigation, interaction, and structured extraction — against arbitrary web pages.
*Why it matters for practitioners:* Replaces fragile scraping glue with a first-class agent tool, making live-web data retrieval a composable step in any agent loop rather than a one-off script.

**vercel/agent-desktop** — https://github.com/vercel/agent-desktop
A Rust-based computer-use CLI that exposes screen, keyboard, and mouse as agent-callable tools, designed as an open harness for local and cloud agents.
*Why it matters for practitioners:* Having a typed, versioned interface for desktop computer-use in Rust (rather than a Python wrapper around OS APIs) matters for reliability and latency in long-horizon agent tasks.

**LoopForge** — https://github.com/loopforge/loopforge
A self-hosted orchestration engine for coding-assistant agents, handling task queuing, checkpoint recovery, and multi-agent fan-out.
*Why it matters for practitioners:* Provides the "boring infra" around coding agents — retries, logging, context windows — so teams can focus on prompt/policy rather than scaffolding.

**Firecrawl** — https://github.com/mendableai/firecrawl
A web-crawl and extraction service built as agent knowledge infrastructure, converting arbitrary URLs into clean markdown context.
*Why it matters for practitioners:* Positions web content as a first-class RAG source for agents, with structured output and depth-first crawl control that naive HTML fetchers lack.

## Trending Papers

**Do LLM Agents Still Need to Be Told How to Self-Improve?** — https://arxiv.org/abs/2611.23219
A Nov 17 paper (Sundaram, Sancaktar, Isola) that asks whether sufficiently capable models can bootstrap their own self-improvement with no externally imposed loop, testing this by giving a frozen LLM a compute budget and experience-collection tools in a game environment.
*Why it matters for practitioners:* If their finding holds — that capable-enough models do self-improve autonomously — it shifts the design question from "what loop do I engineer?" to "is the base model capable enough to seed the loop?"

**R²Orch: Recursive Self-Improvement for Agent Orchestration via Self-Play** — https://arxiv.org/abs/2610.22740
Proposes two nested loops: an inner self-play loop improving an orchestrator on tasks it selects itself, and an outer loop that evolves the inner loop via recursive learnability and skill withdrawal signals.
*Why it matters for practitioners:* Reports gains over all baselines on 12 benchmarks (AIME 2026, WebShop, ALFWorld), suggesting that orchestration quality — not just backbone training — is a primary driver of agent performance.

**SWE-Trail: History-Guided Trajectory Collection for Coding Agent Training** — https://arxiv.org/abs/2611.02074
Exploits prior attempt history to steer *where* trajectory collection effort is spent, while keeping that history out of the agent's context to avoid train-test mismatch — a subtle but important separation.
*Why it matters for practitioners:* A 124B student trained on SWE-Trail trajectories improves over independent sampling by 2.33 pts on SWE-bench Multilingual, with the key design insight being that history is a collection signal, not an agent input.

**Don't Just Trust Your Memory: Evidence-Linked Memory Reduces Memory-Induced Degradation in LLM Agents** — https://huggingface.co/papers/month/2026-11
A Nov 11 paper showing that agents relying on accumulated memory without explicit evidence anchors exhibit systematic degradation; linking each memory entry to source evidence substantially reduces errors.
*Why it matters for practitioners:* Directly relevant to any team building production agents with long-term memory: ungrounded memory accumulation is a silent failure mode that gets worse as memory grows.

**HarnessAdapt-RL: Co-Training Policy and Harness with Reinforcement Learning** — https://arxiv.org/abs/2610.harnessadapt
Co-trains a 9B agent's policy with its tool-and-hook harness during RL rather than fixing the harness and only training the policy, reporting +12.6 pts on SWE-bench Multilingual over GRPO.
*Why it matters for practitioners:* Challenges the assumption that harnesses are static scaffolding; the harness itself is a learnable component, and freezing it during RL training may be leaving significant performance on the table.

## Blog Posts & Articles

**External Sandboxes for Coding Agents** — https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/
Simon Willison's Nov 17 post describes a new open pattern (built with Prime Radiant) where agent-executed code runs inside a dedicated external sandbox while the agent process lives outside it, with three server implementations: v86-in-WebAssembly, Apple Containers, and Microsoft Quicksand.
*Why it matters for practitioners:* Gives teams a concrete, deployable architecture for isolating untrusted code from the agent's own process — especially relevant as local-model coding agents proliferate and prompt-injection risk rises.

**Introducing Harness Adapters: Adapt Your Favourite Model to Your Harness** — https://huggingface.co/blog
Hugging Face researchers (Belkada, Debut, Habib) trained distinct rank-32 LoRA adapters — one per coding agent harness (opencode, hermes, pi) — using RL directly inside unmodified agent environments, rather than a single multi-task model.
*Why it matters for practitioners:* The harness-specialised LoRA approach is a cheaper and more modular alternative to full fine-tuning across harnesses, and the fact that HF is publishing the method with TRL integration means it's immediately adoptable.
