## Trending GitHub Repositories

**Graphify-Labs/graphify** — <https://github.com/Graphify-Labs/graphify>

*Why it matters for practitioners:* Replaces brittle file-grepping in coding agents with a citable graph that can trace call chains and schema relationships — a structurally different retrieval primitive worth evaluating before reaching for a vector DB.

**Mesh-LLM/mesh-llm** — <https://github.com/Mesh-LLM/mesh-llm>
An 18 MB Apache-2.0 Rust binary (launched July 11, 2026) that pools GPUs across machines via iroh peer routing and exposes them as a single OpenAI-compatible API, supporting models up to 235B parameters with built-in speculative decoding (1.5–2.5× throughput gain over naive distributed inference).
*Why it matters for practitioners:* Running a 235B model no longer requires a single expensive cluster — if you have spare GPU boxes across your lab or home network, Mesh-LLM turns them into one endpoint, which meaningfully changes the build-vs-buy calculus for serving large models.

*Why it matters for practitioners:* The clearest working demonstration that hypothesis-testing in ML research can be fully delegated to an agent loop — the pattern (short feedback-loop jobs + structured commit/revert + iterative compounding) is directly portable to other optimization problems.

## Trending Papers

**SIRI: Self-Internalizing Reinforcement Learning with Intrinsic Skills for LLM Agent Training** — <https://arxiv.org/abs/2606.02355>
A new RL training method where the agent self-mines compact skills from its own successful plain rollouts, validates them through paired skill-augmented and skill-free runs, and distills only the beneficial skill-guided tokens back into the base policy — eliminating any need for external skill retrieval at inference time.
*Why it matters for practitioners:* Most skill-based agent training requires an external skill library at inference, adding latency and context overhead; SIRI shows how to bake those skills into the weights themselves during training, making the deployed agent both faster and simpler to serve.

**KLong: Training LLM Agent for Extremely Long-Horizon Tasks** — <https://arxiv.org/abs/2602.17547>
An open-source LLM agent trained for extremely long-horizon tasks using Research-Factory (an automated pipeline that harvests research papers, builds evaluation rubrics, and generates thousands of training trajectories distilled from Claude 4.5 Sonnet Thinking), followed by trajectory-splitting SFT and progressive RL.
*Why it matters for practitioners:* The Research-Factory pattern — auto-constructing long-horizon training data from existing literature — is a directly reusable recipe for anyone building domain-specific agents that need to handle extended task horizons.

**LLMs+Graphs: Toward Graph-Native, Synergistic AI Systems** — <https://arxiv.org/abs/2606.11560>
A survey and research agenda arguing that tightly integrating LLM reasoning with graph algorithms (rather than treating graphs as just another retrieval target) unlocks qualitatively different capabilities: traceable multi-hop reasoning, structured knowledge evolution, and compositional planning.
*Why it matters for practitioners:* As projects like Graphify gain traction, understanding why graph-native retrieval differs from vector + keyword approaches is becoming prerequisite knowledge for anyone designing the knowledge layer of an agent system.

**ROZA Graphs: Self-Improving Near-Deterministic RAG through Evidence-Centric Feedback** — <https://arxiv.org/abs/2604.07595>
A RAG system that builds evidence graphs from each retrieval cycle, then uses discrepancies between expected and actual evidence to self-improve its retrieval strategy over time — no labeled correction data required.
*Why it matters for practitioners:* Near-deterministic RAG (where the same query reliably retrieves the same evidence) is a prerequisite for debugging and evals in production; ROZA shows a self-improving path to that property using only inference-time signals.

**SmoothAgent: Efficient Long-Horizon LLM-Based Agent Serving with Lookahead Context Engineering** — <https://arxiv.org/abs/2607.00151>
A serving framework for long-horizon agents that uses lookahead context engineering — anticipating future context needs based on the agent's current plan — to eliminate wasted prefill computation and reduce per-step latency during extended runs.
*Why it matters for practitioners:* As production agents run for hours (Cognition's SWE-1.7 trains on rollouts up to 6 hours), serving efficiency becomes the dominant cost driver; SmoothAgent offers a principled framework for managing that cost without sacrificing agent capability.
