## Trending Papers

**SWE-chat: Coding Agent Interactions From Real Users in the Wild** — https://arxiv.org/abs/2604.20779
A large-scale dataset of 6,000 real coding agent sessions (63K+ user prompts, 355K agent tool calls) across 200+ public repos.
*Why it matters for practitioners:* The empirical finding that only 44% of agent-produced code survives into user commits — and that agent-written code introduces more security vulnerabilities than human-authored code — is a direct challenge to unchecked "let the agent write it all" workflows.

**CompactionRL: Reinforcement Learning with Context Compaction for Long-Horizon Agents** — https://arxiv.org/abs/2607.05378
Trains long-horizon agentic LLMs via RL with joint optimization of task execution and context summarization using token-level loss normalization and cross-trajectory GAE.
*Why it matters for practitioners:* Addresses the core scaling problem for coding agents (context overflow) by training the model itself to compress rather than relying on hard-coded summarization — GLM-4.5-Air reaches 66.8% on SWE-bench Verified with this approach.

**SWE-MeM: Learning Adaptive Memory Management for Long-Horizon Coding Agents** — https://arxiv.org/abs/2606.28434
A training framework for proactive, on-demand memory management in SWE agents, using Memory-aware GRPO for joint optimization of compression and task resolution.
*Why it matters for practitioners:* 60.2% SWE-bench Verified with a 30B model (vs. fixed-compression baselines) suggests that learned memory management is a higher-leverage intervention than scaling model size alone.

**Stateful Governance for Concurrent Agentic Systems** — https://arxiv.org/abs/2608.02764
A governance architecture that maintains a compact policy state vector per agent task, enabling stateful, temporal, and resource-based policy evaluation at constant time.
*Why it matters for practitioners:* As agents move from single-action to multi-step workflows touching real systems (payments, cloud infra, data), this paper provides a concrete runtime governance model — the "managed state vector" pattern is directly implementable.

**When Should Active RAG Retrieve? A Budget-Aware Evaluation of Utility, Calibration, and Cost** — https://arxiv.org/abs/2607.24010
A systematic evaluation of active RAG retrieval policies, measuring when retrieval helps vs. hurts across utility, calibration, and per-query cost dimensions.
*Why it matters for practitioners:* Most RAG deployments retrieve on every query by default; this paper gives you the empirical basis to build cost-aware retrieval gating, which is the difference between a research demo and a production system.
