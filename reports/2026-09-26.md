## Trending GitHub Repositories

**google/ax** — https://github.com/google/ax
Google's open agentic orchestration runtime: declare Tasks, Workspaces, Gateways, and Models in YAML (Kubernetes-style manifests) and `kubectl apply` your agent fleet into a sandboxed cluster.
*Why it matters for practitioners:* It treats agent workloads as schedulable cluster resources — isolation, MCP server pre-wiring, and LLM config via Secrets — giving teams a repeatable path to production multi-agent deployments without bespoke infrastructure.

**vectorize-io/hindsight** — https://github.com/vectorize-io/hindsight
State-of-the-art long-term memory layer for AI agents, built by Vectorize, organizing memories across four biomimetic networks (World facts, Experiences, Observations, Mental models) with Retain/Recall/Reflect operations.
*Why it matters for practitioners:* Agents with Hindsight maintain context across sessions without bloating the prompt window, and the MIT-licensed, self-hostable design means you can wire it into any agent harness — Claude Code, Codex, Gemini CLI — as a drop-in memory backend.

**karpathy/autoresearch** — https://github.com/karpathy/autoresearch
AI agents that autonomously run ML experiments on the nanochat LLM training harness overnight: modify code → 5-minute training run → check validation loss → keep or discard → repeat.
*Why it matters for practitioners:* It's a working example of closing the research loop without human checkpoints — if it generalizes, the cost of an ML ablation drops from an engineer's day to a GPU night.

**paperclipai/paperclip** — https://github.com/paperclipai/paperclip
Open-source operating system for multi-agent companies: an org-chart for agents with roles, permissions, approval gates, skill studio, evals, and cross-provider runtime, built on top of a sandboxed Agent Substrate.
*Why it matters for practitioners:* It provides the management layer that most agent frameworks skip — not just "run a task" but "track work, control costs, gate approvals, and train agents on your company's skills."

**zai-org/ZCode** — https://github.com/zai-org/ZCode
Z.ai's open-source coding agent harness (TypeScript, Apache 2.0, 6.1k stars): extensible client + backend + agent CLI architecture for building and running AI coding agents.
*Why it matters for practitioners:* As coding agents mature past one-shot code completion into multi-step autonomous workflows, ZCode's pluggable adapter model (Kimi Code and others) lets teams swap underlying models without rewriting their harness.

## Trending Papers

**MAGIC: Mixed-Granularity Agent Graphs via Incremental Construction with Dense-Reward RL** — https://arxiv.org/abs/2609.26667
A new method for building multi-agent systems that incrementally assigns each functional role as either a single agent or a reusable group, constructing the collaboration graph with RL-shaped dense rewards based on probe-based utility and structural signals.
*Why it matters for practitioners:* Rather than picking a fixed topology upfront, MAGIC lets the system discover when subtasks warrant a team vs. a single specialist — outperforming fixed-topology baselines across eight benchmarks with better inference efficiency.

**AgentGym-RL: Training LLM Agents for Long-Horizon Decision Making through Multi-Turn RL** — https://arxiv.org/abs/2509.08755
ICLR 2026 Oral paper introducing a modular multi-turn RL training framework (ScalingInter-RL) for long-horizon agent tasks, releasing full code and datasets; agents trained with it match or surpass o3 and Gemini-2.5-Pro across 27 diverse tasks.
*Why it matters for practitioners:* It's an open-source recipe for training capable long-horizon agents from scratch, with staged curriculum training that prevents the reward-hacking and instability that plague naive RL on long trajectories.

**Connect the Dots: Training LLMs for Long-Lifecycle Agents with Cross-Domain Generalization via RL** — https://arxiv.org/abs/2606.20002
A framework for training LLMs on the "Connect the Dots" meta-capability: agents that solve a long sequence of tasks, update their context from experience, and generalize to new domains they weren't trained on.
*Why it matters for practitioners:* It's the first demonstration that end-to-end RL can produce genuine cross-domain transfer for long-lifecycle agents — a direct counter to the assumption that agents need per-environment fine-tuning.

**RePro: Retrospective Progress-Aware Self-Refinement for LLM Agent Training** — https://arxiv.org/abs/2606.14302
Trains agents to generate their own step-wise progress signals via a forward-then-reflect paradigm: execute online, then retrospectively assess progress given the completed trajectory and known outcome.
*Why it matters for practitioners:* Agents optimized only for action prediction lack awareness of whether they're making progress on the overall task; RePro injects that metacognition without continuous external supervision, achieving consistent gains across three benchmarks and three model scales.

**Mem-α: Learning Memory Construction via Reinforcement Learning** — https://arxiv.org/abs/2509.25911
An RL framework that trains agents to decide what to store, how to structure it, and when to update it — instead of relying on pre-defined memory tool instructions.
*Why it matters for practitioners:* Even GPT-4o struggles with correct memory tool selection when the tool set grows complex; Mem-α learns the policy through feedback, making it the right approach for agents with evolving or compound memory architectures.
